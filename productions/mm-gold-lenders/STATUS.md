## Dry-run notes
(what broke at each handoff, to fix in the contracts; this is the first run of the chain on a script written before research)
1. **Contract 01 assumes research comes before the script.** Here a ledger with "OK" statuses already existed. The research role had to keep the script's IDs (no renumbering), re-verify each, and sweep every SAY line for assertions with no ID. That last sweep produced U1-U9; contract 01 has no such step and no home for "unsourced script lines". Suggest: when a script exists, research also returns a "script lines without a claim" list in `open_questions.md`.
2. **Ledger locators were not the chain's.** The ledger cites printed pages ("p.2 and p.8" = PDF pp.3 and 9), a consolidated GNPA table as standalone, and an IIFL page that is another slide. The ledger's "OK" is not evidence; the fact-checker should not rely on it.
3. **G3 and G4 are inventor-shaped.** Full mode's 10 categories (patents, newspapers, books, journals, oral histories, original language) mostly do not apply to a company-and-regulator analysis, so G3 passes only by written skip reasons under `## Category n` headings, and G4's "last 4 sources add nothing" (saturation) was not met because the source set is fixed by the script. COMMON.md section 1 sends Moat & Margin to these rules "until AK names its own file" (open item, section 12); this run is a reason to write that file.
4. **Claim ID format.** COMMON.md section 3 says `C001`; the script uses `C1`, `R1`, `W2`, `J1`, and `C1+C2`. The gate does not care; the contract should say "keep the script's IDs when a script exists".
5. **Tooling facts worth adding to COMMON.md section 9.** NSE archive PDFs download with plain curl and a browser user agent at `https://nsearchives.nseindia.com/corporate/<filename>.pdf` (the filenames in the ledger match). rbi.org.in notification and press-release pages carry the full text inline, but RBI's own PDF and xlsx links and the WGC report PDF return a bot-challenge or 403 to curl; the web page is the saved copy. Fetched RBI pages need cleaning to text before the gate's quote re-find.
6. **"Publisher's own site".** The brief says fetch from the publisher's site; the filings' only copy is the exchange's (NSE archive). COMMON.md section 2 does not say whether an exchange-hosted copy counts as the publisher's. Recorded as exchange-filed copy; open_questions.md item 3 asks for a company-site comparison before publishing.
7. **Scanned filings.** Titan's outcome PDF is a scan with an OCR text layer (rupee sign reads "~", digits split). The gate's quote re-find then only matches the OCR text, which is not what the page says. COMMON.md section 7 should say: quote the OCR text, note it, and verify on the rendered page.
8. **Jumbled chart text.** PyMuPDF returns deck charts as blocks of numbers (SBI p.11, Manappuram p.20). Mapping values to labels needed arithmetic cross-checks and one rendered image. Suggest a contract line: for chart slides, verify by rendering or by a sum.
9. **Tiers.** COMMON.md section 2 gives company filings P4 and regulator orders P2; RBI Directions and press releases were P2; WGC (the data owner) P4 with no `self_claim`. No conflict found, but regulator press releases are not "orders": worth a line.
10. **Spine for an analysis film.** Contract 01's rule ("every number the hook or the answer could rest on, every attributed quote, every allegation") needed extending to "every spoken number, every attributed quote, every RBI rule", as the brief did. Arithmetic claims (A1, C1+C2) have no source document; I gave them `type: calculation`, `VERIFIED-P`, the defining text as evidence, and an "our calculation" note. COMMON.md section 4 has no status for "our arithmetic".
11. **Duplicate archive files.** The results archive held two byte-identical Muthoot press releases (152912 and 153100); the ledger names 152912. No effect.
